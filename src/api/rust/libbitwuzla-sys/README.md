# libbitwuzla-sys

Low-level FFI bindings for the [Bitwuzla](https://bitwuzla.github.io) SMT
solver, generated by [bindgen](https://github.com/rust-lang/rust-bindgen) from
the C API headers (`bitwuzla/c/bitwuzla.h`, `bitwuzla/c/parser.h`).

For a safe, idiomatic API, use the `bitwuzla` crate.

This crate is unrelated to the `bitwuzla-sys` crate on crates.io. Both link
`libbitwuzla` (`links = "bitwuzla"`), so Cargo rejects a build that depends on
both.

All items have their C names (see the
[C API documentation](https://bitwuzla.github.io/docs/c/api.html)), e.g.,
`bitwuzla_mk_term`, `BitwuzlaTerm`. C enums are integer type aliases with one
constant per value, e.g., `BitwuzlaKind` and `BITWUZLA_KIND_BV_ADD`.

All functions use the `"C-unwind"` ABI, so an abort callback (see
`bitwuzla_set_abort_callback`) may unwind back into Rust.

See `build.rs` (or the `bitwuzla` crate's README) for how Bitwuzla is located.
The bindings require Bitwuzla `MIN_BITWUZLA_VERSION` (the version of this
crate) or newer; the build script rejects older libraries. At run time, the
library must be of the release the bindings were generated for, since
releases may renumber C enum values: `is_compatible_version` checks the
version `bitwuzla_version` reports.

| Feature  | Description                       |
|----------|-----------------------------------|
| `static` | Link Bitwuzla statically.         |

The build script also generates the Rust enums of the `bitwuzla` crate from
the same headers, so they match the linked library.

`prebuilt/` contains the generated files for docs.rs, where neither Bitwuzla
nor its headers are available. A test checks that they are up to date when
building inside the Bitwuzla source tree; update them with
`UPDATE_PREBUILT=1 cargo test -p libbitwuzla-sys`.
